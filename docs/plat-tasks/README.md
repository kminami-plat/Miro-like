# 今日のボードとアーカイブ（plat-todo 連携）

ホワイトボードの既定の画面は、**社員 × ステータスの固定グリッドに付箋を貼るボード 1 枚**です。

```
サインイン → 今日のボード（/） → 必要なら アーカイブ（/archive → /archive/2026-09-25）
```

付箋 1 枚が、社内タスクハブ（https://pm.plat-yonezawa.com/plat-todo/）のタスク 1 件です。データは
Cloudflare の plat-kv に、plat-todo と同じ型（`plat-todo-tasks`）で保存されるので、どちらで編集しても
もう一方に反映されます。ボードは営業日の終わりに自動で記録され、1 か月分をその時点のまま閲覧できます。

設計の詳細は [DESIGN.md](DESIGN.md)、手動確認の手順は [CHECKLIST.md](CHECKLIST.md) を参照してください。

## 今日のボード

- 行 = 社員、列 = 未確定 / 未着手 / 進行中 / 相手待ち / 完了。最後に「担当なし」の行
- マスは付箋の数に合わせて伸びます。マスにカーソルを乗せて **＋** → 書いて Enter で貼り、すぐ次の付箋が
  開きます（連続で書けます）。Esc か何も書かずに外をクリックすると閉じ、**空の付箋は保存されません**
- 付箋をクリックすると、その場で文字を書き換えられます（Enter で確定、Esc で取り消し、文字を全部消すと削除の確認）
- 付箋の **⋯** で詳細（担当者・ステータス・優先度・事業領域・プロジェクト・期限・メモ）
- 付箋をドラッグ: 別の列 = ステータス変更、別の行 = 担当者の付け替え（他の担当者はそのまま）
- 付箋には内容、メモ、プロジェクト、期限（過ぎたら ⚠ と赤字）、優先度、重いの印が出ます
- 行見出しに 未完了 / 重い / 期限切れ の件数。完了列は各マス最新 5 件まで（「すべて表示」で全件）
- フィルター: 事業領域、プロジェクト、期限切れのみ、プロジェクト日程の表示/非表示（ブラウザに記憶）
- プロジェクトの日程タスク（`tasks-<projectId>`）は青い点線の付箋。クリックでプロジェクトページが開きます（編集不可）

### 行（社員）の管理 — 新入社員

管理者には **行を編集** ボタンが出ます。ID と表示名で行を追加し、名前・役職・並び順・表示/非表示を
変えられます。ID はタスクの担当者として plat-todo と共有されるので、名簿（people.json）と同じ ID
（例: `sato-hanako`）にしてください。名簿に入っている人、担当者として使われている ID も自動で行になります。
退職者などを非表示にしても、その人の付箋が残っている間は表示されます（付箋が見えなくならないように）。

## アーカイブ

- **営業日** = 土日・国民の祝日（振替休日・国民の休日を含む）以外の日。会社独自の休み（年末年始など）は
  `ARCHIVE_EXTRA_HOLIDAYS` で追加します
- 各営業日の **締め時刻**（既定 24:00）の時点のボードを 1 件記録し、**31 日間**保存します
- アーカイブ画面は月〜金のカレンダーです。黄色 = 記録あり、赤 = 記録できなかった日、点線 = 休日・記録開始前、
  青い点線 = 今日（まだ締め前）
- 日付を選ぶと、その日のボードが**閲覧専用**で開きます（付箋の追加・移動・書き換えはできません）。
  期限切れの判定はその日の日付で行います。「前の営業日 / 次の営業日」で移動できます
- 記録はスクリーンショットではなくデータで保存し、同じ画面で描き直しています（文字は選択・コピーでき、
  フィルターも使えます）

### 記録のタイミングと、サーバーが寝ている場合

記録は次のどれかで行われます（同じ日は 1 回だけ）。

1. サーバー内のタイマー（1 分ごとに確認）
2. このアプリで誰かが付箋を編集したとき — **編集を反映する前に**前日分を記録するので、翌朝の編集が
   前日の記録に混ざることはありません
3. 外部の cron からの `POST /api/archive/run`（ヘッダー `X-Archive-Secret: <ARCHIVE_CRON_SECRET>`）

**Render の無料プランは 15 分操作がないと停止する**ため、締め時刻にサーバーが寝ていると 1 のタイマーが
動きません。その場合、翌朝に既存ページ（plat-todo）で行われた編集が記録に混ざりえます（2 はこのアプリの
編集しか防げない）。正確にしたい場合はどちらかにしてください。

- Render を有料プラン（Starter）にする
- 外部 cron で締め時刻の数分後に 3 を呼ぶ。例（Cloudflare Workers の Cron Trigger、cron-job.org、
  GitHub Actions など。24:00 締めなら平日の翌 0:05 JST = 15:05 UTC）:
  ```bash
  curl -X POST -H "X-Archive-Secret: $ARCHIVE_CRON_SECRET" https://<ホワイトボードのURL>/api/archive/run
  ```

締め時刻から 30 分以上遅れて記録された日は、カレンダーとボードに「遅れて記録」と実際の記録時刻が出ます。

## セットアップ

`.env`（ローカル）またはホスティングの環境変数に設定します。**トークンは Git に入れないでください**
（`.env` は `.gitignore` 済み）。変更後はサーバーを再起動してください。

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PLAT_KV_TOKEN` | なし | Worker の書き込みトークン（`X-Plat-Token`）。未設定ならボードは閲覧のみ |
| `PLAT_LOCAL_ONLY` | なし | `1` でトークンなしでも編集可。変更は `data/plat/local_kv.json` にだけ保存され、Worker へは一切書き込まない（未編集のキーは Worker から読む） |
| `PLAT_TASKS_KEY` | `plat-todo-tasks-sandbox` | 読み書きするキー。本番は `plat-todo-tasks` |
| `ARCHIVE_CUTOFF` | `24:00` | 営業日を締める時刻（JST、`HH:MM`）。例: `18:00` |
| `ARCHIVE_DAYS` | `31` | 記録を残す日数 |
| `ARCHIVE_EXTRA_HOLIDAYS` | なし | 会社の休日（`2026-12-29,2026-12-30,…`） |
| `ARCHIVE_CRON_SECRET` | なし | 外部 cron 用の合言葉（長いランダム文字列） |
| `LEGACY_BOARDS` | なし | `1` で従来のボード一覧・作成・キャンバスを再び有効化（`/` はボード一覧、今日のボードは `/today`） |
| `PLAT_KV_URL` | `https://plat-kv.k-oda.workers.dev` | Worker の URL |
| `PLAT_ACCESS_CLIENT_ID` / `PLAT_ACCESS_CLIENT_SECRET` | なし | Cloudflare Access のサービストークン。people / domains / projects.json の取得用 |
| `PLAT_LOCAL_DATA_DIR` | `data/plat` | 上記 JSON のローカルコピーを置くフォルダ |
| `PLAT_PROJECT_IDS` | なし | 日程を表示する追加のプロジェクト ID（カンマ区切り） |

起動ログに `plat tasks: key=…`、`boards: 今日のボードのみ` と出ます。

### トークン

1. トークンを管理者から受け取る
2. ローカル: `.env` に `PLAT_KV_TOKEN=…` を 1 行追加。Render: ダッシュボードの Environment に追加
3. 再起動し、ボード右上に「閲覧のみ」の案内が出ていないことを確認

トークンはサーバーの中だけで使われ、ブラウザには送られません。

### 社員名簿・事業領域・プロジェクト

これらは Cloudflare Access の内側にあるため、Access のサービストークン（`PLAT_ACCESS_CLIENT_ID/SECRET`）か、
`data/plat/` に置いたローカルコピーから読みます。どちらもなくても、管理者が「行を編集」で名前を付ければ
ボードは使えます。将来ホワイトボード自体を Cloudflare Access の内側に置く場合も、この仕組みはそのまま使えます。

## サンドボックスから本番への切り替え

1. サンドボックスに本番のコピーを入れる（トークンが必要。サンドボックスキーにだけ書き込みます）:
   `.venv/bin/python scripts/seed_plat_sandbox.py`
2. `PLAT_TASKS_KEY` 未設定（= サンドボックス）のまま [CHECKLIST.md](CHECKLIST.md) の A 節を実施
3. 承認後、`PLAT_TASKS_KEY=plat-todo-tasks` を設定して再起動。黄色の「サンドボックス」表示が消えます
4. 本番で CHECKLIST.md の B 節を実施

サンドボックス期間中のアーカイブはサンドボックスの内容です（記録にはキー名も残ります）。

## 既知の制限

- プロジェクトの日程タスクは閲覧のみ（安定した ID がないため）
- 付箋の文字は 1 行（plat-todo のタイトルと同じ）。長い説明は ⋯ の「メモ」に書きます
- **`effort`（重さ）**: 仕様どおり `重い` / `L` / `M` を重いと数えますが、現在の本番データの `effort` は
  数値の `1` / `2` なので、今は常に 0 件になります（`server/plat_tasks.py` と `static/plat_store.js` の `HEAVY`）
- 既存ページと完全に同時に保存した場合の競合は防げません（Worker に条件付き書き込みがないため）
- アーカイブは日単位で 1 件だけです（途中の状態は残りません）。祝日の計算は 2022〜2099 年の現行法に基づきます
- ドラッグ＆ドロップはマウス向けです（スマートフォンでは ⋯ からステータス・担当者を変更）
- 書き込めるのはサインインできる人全員です。公開する場合は `REGISTRATION_CODE` を設定してください
- 既存ページ側の変更は最大 60 秒遅れて反映されます（ウィンドウに戻ったときは即時）
